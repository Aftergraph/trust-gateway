From clone to governed bots

Quickstart

Four steps. No Docker, no Postgres, no Bun — the gateway runs on Node core alone.

Run it

# 1. Clone
git clone <your-fork-url> trust-gateway && cd trust-gateway

# 2. Write your env file (gitignored — data/ never enters git).
#    Use placeholder tokens here, real ones only on your machine.
mkdir -p data
cat > data/gateway.env <<'EOF'
BOT_TOKENS=atlas:your-operator-token,forge:your-worker-token
EOF
chmod 600 data/gateway.env

# 3. Source it and start the gateway with the jailed per-bot dispatcher
source data/gateway.env
node bin/gateway.js --dispatch

# 4. Open the console
#    http://localhost:8800        — operator console (dashboard + audit)
#    http://localhost:8800/home   — this public site
#    http://localhost:8800/healthz — public chain snapshot (no auth)

atlas is the operator (may approve or deny); every other bot is a worker that fails closed on approval endpoints. The --dispatch flag enables the per-bot jailed dispatcher: each bot gets its own directory under data/bots/ and its own tool access — nothing shared between bots, and your own sign-ins stay yours. Rotate tokens by editing data/gateway.env and restarting; old tokens die with the restart, and rejected attempts land in the audit trail.

Public API surface

Everything an authenticated bot or operator can call. Nothing here is hidden, and nothing sensitive is needed to evaluate the design — /healthz is the only endpoint that answers without a token.

Method & pathAuthWhat it does
GET /healthz None (public) Liveness + audit-chain snapshot: ok, entry length, head hash. This is what the status page reads.
POST /v1/actions Bearer bot token Submit a tool action. The fail-closed policy engine answers allow, deny, or 202 needs_approval — before anything executes.
GET /v1/approvals Bearer bot token List pending human approvals (bot, tool, reason, expiry).
POST /v1/approvals/:id/approve · /deny Bearer operator token Resolve a pending approval. The decision is itself an audited chain entry. Workers fail closed here.
GET /v1/audit Bearer bot token Audit entries since a sequence number, plus current verification state. Secrets never appear — only their length.
GET /v1/audit/verify Bearer bot token Re-verify the full hash chain from genesis. Same verdict the /healthz snapshot reports publicly.
GET /home None (public) This site.

Unauthenticated requests to anything except /healthz and /home get a 401 — and the rejection itself is written to the audit chain.
